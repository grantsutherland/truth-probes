Gemma-2-2B and Gemma-2-9B. The original thread was a mechanistic account of

CRITICAL METHOD NOTE, applies to every NIE number ever quoted here: NIE divides

2. CODE — WHAT EXISTS AND IS VALIDATED
--------------------------------------------------------------------------------
src/probes.py
  - TruthProbe(nn.Module, ABC): shared base. nn.Linear(d_model, 1) holds the
    direction + bias. from_data() classmethod (alt constructor, dispatches via
    cls), abstract _fit(), forward() (raw margin), predict() (sign), score()
    (accuracy), direction (@property, unit-normalized + detached).
  - LRProbe: torch/Adam, BCEWithLogitsLoss, full-batch. Defaults under-train on
    real activations; use lr=1e-2, epochs=2000 (used everywhere downstream).
  - MMProbe: closed-form difference-of-means; iid flag adds Sigma^-1 whitening
    (LDA) with a ridge. requires_grad turned off after fit.
  - PROBES = {"lr": LRProbe, "mm": MMProbe} registry.
  - VALIDATED on synthetic 2-Gaussian data: accuracy, direction recovery, unit
    norm, idempotent direction read all pass.

src/config.py  [NEW 2026-07-23 — the one place the model is named]
  - MODEL_NAME (currently "gemma-2-9b"). Change here + re-run 01 to switch models,
    or set TRUTH_PROBES_MODEL=gemma-2-2b for a one-off cross-model re-run without
    editing-and-reverting the constant (which is how numbers get mislabelled).
  - chosen_layer()   -> reads results/<model>/layer_sweep.json, errors loudly if
    that sweep was built by a DIFFERENT model than MODEL_NAME.
  - plateau_layers() -> contiguous run around the peak within PLATEAU_TOL (0.02).
    Contiguity is load-bearing: at 9B a plain threshold would wrongly admit L13,
    which clears the floor but is separated from the peak by the L14-16 dip.
  - spot_layers()    -> 3 layers around the peak, stepping further out on one side
    when the peak sits at a band edge (which it does at 9B: peak L17 = plateau lo).
  - RESULTS_DIR = results/<MODEL_NAME>/  (see scoping note below).
  - VALIDATED: reproduces the 2B hand-picked values EXACTLY (13, [11..17],
    [11,13,15]) and returns 3 spot layers at 9B ([17,19,21]).

src/lastping.py  [NEW — optional job-progress heartbeats]
  - stdlib only, no-op when unconfigured, never raises. Sends per-dataset progress
    from inside 01's extract loop. IngestHeartbeat accepts ONLY
    run_id/step/metric/text — anything else 422s.
  - Fails open but NOT silent: the first failure prints status+body to stderr once.

src/data.py  (uses pandas; all disk I/O centralized here)
  - load_statements(name): parse M&T CSVs (statement/label cols) -> texts, labels.
  - save_activations/load_activations: single-layer canonical cache. Casts acts
    -> float32, labels -> float on load (probes stay dtype-dumb).
  - save_sweep/load_sweep/sweep_exists: all-layer intermediate cache (Option 1).
  - save_probe/load_probe: persist/reload trained probes (03/04 reuse, no retrain).
  - train_test_split (seeded), compute_mean_offset, center.
  - CACHE_VERSION guards stale caches. DATASETS registry.

src/activations.py  (TransformerLens)
  - load_model(): auto device (cuda>mps>cpu), sensible dtype default, eval mode.
  - verify_model(): LOAD CHECK — runs one forward, confirms
    blocks.{layer}.hook_resid_post exists with right shape. RUN THIS FIRST.
  - extract_activations(): batched, all requested layers in ONE forward pass,
    last-real-token (end-of-statement) gather, robust to padding side, -> float32.

WHITENED-ALIGNMENT CHECK (results/whitened_alignment.json)
  - Tested M&T theory: unregularized LR -> Sigma^-1 theta_mm (needs n >> d).
  - RESULT: the tilt is NOT the covariance correction AT THIS REGIME. Real
    whitening (small ridge) DEGRADES cos(iid, lr); large ridge -> back to plain MM.
  - CAUSE: d_model 2304 > n_train for every dataset -> within-class covariance is
    rank-deficient -> Sigma^-1 noise-dominated. M&T's "enough data" premise fails.
  - Genuinely testable only where n >> d (9B, or concatenated datasets).

TRANSFER / H1 (results/transfer.json), AUROC-first
  - IMPORTANT CORRECTION #1: the first pass reported raw accuracy and hit exactly
    0.500 in 16 cells. That was a BIAS-TRANSFER ARTIFACT (constant prediction),
    NOT a direction failure: the trained bias (train-set midpoint) lands off the
    test set's projection distribution. Caught and fixed. Do NOT cite the raw-acc
    transfer numbers as evidence of "no shared direction."
  - The BIAS does not transfer; the DIRECTION does. This is exactly why M&T center
    + use unbiased probes. Correct protocol = per-dataset SELF-centering at
    use-time (NOT a single stored offset centering all datasets by cities' mean).

  - TASK A (signed vs sign-folded — do NOT fold sign silently):
      * FOLDED metrics max(a,1-a) use TEST labels to pick each direction's sign =
        SIGN-ORACLE. They answer "does the direction carry truth info," NOT "does
        the probe transfer usably." M&T report SIGNED accuracy; only signed
        numbers are comparable to their table.
      * Signed off-diag means (MM/LR): AUROC 0.597/0.603, centered-acc 0.575/0.579.
        BUT these means sit in the empty valley of a BIMODAL distribution — no
        real cell takes ~0.60. Reporting the mean is misleading here.
      * BANDED counts over the 30 off-diagonal cells (signed AUROC), the honest
        summary. MM: >=0.9: 9 | 0.7-0.9: 6 | 0.3-0.7: 8 | 0.1-0.3: 1 | <0.1: 6.
        LR:  >=0.9: 9 | 0.7-0.9: 7 | 0.3-0.7: 6 | 0.1-0.3: 2 | <0.1: 6.
        => 15/30 at the extremes: the direction is either right or exactly
        backwards, almost never confused. Bimodality is STRUCTURE, not noise.

  - HEADLINE (H1, clean): cross-TOPIC transfer, affirmative->affirmative, SIGNED,
    no oracle, EXCLUDING the two larger<->smaller cells that are logical
    complements BY CONSTRUCTION (stated a priori, not "dropping the worst cells"):
        MM 0.8425, LR 0.8781.
    A probe trained on city facts ranks Spanish-English translations correctly
    (cities<->sp_en_trans ~1.0 both ways; smaller_than->cities/sp_en ~0.99).
    This is a real reproduction of M&T's core claim at 2B — what H1 asked.

  - SIGN FLIPS track two KNOWN, a priori causes (dataset properties, not failures):
      * negation: sp_en_trans <-> neg_sp_en_trans AUROC ~0.001/0.000 (CLEAN flip).
      * logical complement: larger_than <-> smaller_than ~0.003/0.020 (CLEAN flip).

  - THE RESIDUAL OPEN QUESTION lives in the 0.3-0.7 band (8 cells, MM), where
    signal genuinely DEGRADES rather than inverting:
      * cities <-> neg_cities: 0.417/0.345 (negation degrades cities, unlike the
        clean inversion it causes for translation — Task B investigates whether
        this is a statement-type property or a layer-13 slice artifact).
      * factual -> larger_than specifically weak (cities->larger 0.641,
        sp_en->larger 0.517), while ->smaller_than transfers cleanly (0.92-0.99).
        Asymmetry within the numeric pair; parked.

  - TASK B (results/negation_by_layer.json) — is the negation asymmetry a
    layer-13 artifact? Swept all 26 layers, 4 directed AUROC pairs + cosine
    between A-trained and B-trained directions.
      * BOTH negation pairs trace the SAME rotation: antipodal (early) ->
        orthogonal (late), matching M&T's documented negation rotation. (We see
        antipodal->orthogonal only, NOT M&T's later re-aligning, within 26 layers.)
      * They differ in RATE: factual (cities) negation rotates EARLIER than
        translation. Cosine shows a SUSTAINED gap L4-17 (e.g. L8 -0.47 vs -0.60,
        L11 -0.33 vs -0.61, L13 -0.02 vs -0.42), not a narrow window. AUROC makes
        it look narrow only because AUROC saturates near 0 until cosine nears
        orthogonal, then swings fast. COSINE is the honest measure here.
      * VERDICT: the strong claim "negation cleanly inverts translation but
        DEGRADES cities as a statement-type property" does NOT survive the sweep.
        At L8-11 BOTH pairs cleanly invert (no asymmetry). The real result is the
        weaker one: factual-negation rotates to orthogonal at earlier depth than
        translation-negation. Killed my own most-interesting claim; correct call.

  - LAYER-ROBUSTNESS CHECK (results/transfer_by_layer.json) — layer 13 was the
    argmax of a SATURATED metric (in-dist acc all >0.976 across L11-17), so re-ran
    the full transfer analysis across the plateau L11-17:
      * Cross-topic transfer (aff excl complements) is ROBUST: MM 0.72-0.90,
        LR 0.81-0.90 across the whole plateau. L13's 0.84/0.88 is mid-pack, NOT
        cherry-picked. The M&T core reproduction does not depend on layer choice.
      * Bimodal banded structure ROBUST too (~6-9 clean transfers, ~6-9 clean
        inversions at every plateau layer).
      * The ONE layer-contingent cell is cities->neg_cities: 0.006 (clean
        inversion) at L11 -> 0.417 (degraded) at L13. And L13 is the GLOBAL
        cosine extremum (closest to orthogonal, -0.023) for cities<->neg_cities
        across all 26 layers — i.e. the accuracy-selected layer is coincidentally
        the single WORST layer for cities-negation transfer. This is the residual
        "degraded" band from Task A: a rotation-phase artifact, now explained.
      * Transfer actually peaks ~L15; an accuracy-selected layer differs
        marginally from a transfer-selected one, but no conclusion changes.

REVISED H1 CONCLUSION (replaces the earlier premature negative):
  At Gemma-2-2B the truth direction transfers RELIABLY within sign-consistent
  families (cross-topic signed AUROC ~0.84 MM / ~0.88 LR, no oracle, ROBUST
  across plateau layers 11-17) and INVERTS PREDICTABLY across negation and
  logical complementarity. Failures are structured and interpretable, not noise.
  Negation is a depth-dependent ROTATION (antipodal->orthogonal), faster for
  factual than translation statements; the layer-13 "cities-negation degrades"
  appearance is a slice of that rotation, not a statement-type property. The bias
  does not transfer, so threshold-free / centered eval is required. LR and MM
  transfer comparably.
  STANDING CAVEATS: primarily layer 13 (headline verified robust L11-17),
  Gemma-2-2B only, laptop MPS numbers.

6. KEY DECISIONS / GOTCHAS TO REMEMBER
--------------------------------------------------------------------------------
- Probes are torch nn.Modules (not sklearn) — the README was updated to match.
- LR defaults under-train; always pass lr=1e-2, epochs=2000.
- AUROC is the honest transfer metric here; raw accuracy is confounded by bias
  transfer on distribution shift. Always sanity-check exact-0.500 cells.
- Centering: per-dataset self-centering, label-free, at eval time. The
  mean_offset-in-cache mechanism is the wrong abstraction; caches stay raw.
- MM direction is causally-motivated; LR may be nuisance-contaminated — the point
  of H2. cos(mm,lr) ~0.77 in-distribution is the thread linking H1 and H2.
- Layer sweep uses MM for SELECTION (its direction is what H2 leans on); LR curve
  recorded for comparison.

- **TransformerLens upcasts the state dict to fp32 during weight processing**
  (weight_processing.py: `state_dict[k] = v.float()`). dtype=bfloat16 does NOT
  bound peak memory. Measured peak HOST RSS for gemma-2-9b: 116 GiB in the verify
  job, 151 GiB in extraction. Request >=176G. A 128G job would have OOM'd.
  This is why gpu_devel (hard QOS cap: cpu=4, gpu=2, mem=32G) CANNOT run 9B at
  all — it OOMs during load, before any forward pass. Use partition `gpu`.
  Do NOT "fix" this with from_pretrained_no_processing: it changes the
  activations and breaks comparability with the 2B numbers.
- google/gemma-2-9b on HF is **34.5 GiB (fp32 weights, 8 shards)**, not the
  18.5 GB a bf16 checkpoint would be. 18.5 GB is what it occupies on the GPU
  after the cast. Download took 73s on Misha (~470 MB/s). VRAM peak is only
  ~21 GiB, so VRAM was never the constraint — host RAM was.
- **`sbatch --test-only` start estimates are worst-case and wildly pessimistic.**
  It projected a ~2-day wait for the gpu partition (462 pending / 117 running);
  the job actually started IMMEDIATELY. Submit and look, do not plan around the
  estimate. GPU type made no difference to the estimate either.
- HF_HOME is set to /gpfs/radev/project/krishnaswamy_smita/gss34/hf_cache
  (project has ~1.2 TB free; home is 61/125 GiB and already holds a 12 GiB cache).
- HF gating: `model_info()` SUCCEEDS on a gated repo you cannot access. Only an
  actual file fetch (hf_hub_download of config.json) proves the license grant.
- `/tmp` on compute nodes is node-local — scripts must live on GPFS to be visible
  from a job.
- Caches AND results are now scoped by model (see section 2). `sweep_exists()` is
  what 01 uses to skip already-extracted datasets; before scoping, a stale 2B
  cache would have satisfied that check during the 9B run and silently skipped
  extraction, leaving every 9B number computed on 2304-dim 2B activations.
- The layer is no longer hardcoded anywhere. THREE separate 2B constants existed
  (`LAYER = 13`, `LAYERS = [11,13,15]`, and `load_model("gemma-2-2b")` inside
  aux_nie_intervention.main) — each would have silently produced wrong-but-
  plausible 9B output. All now derive from src/config.py.
- aux_nie_intervention.true_false_ids took `to_tokens(...)[0,0]` — the FIRST
  token — which silently returns a fragment if " TRUE"/" FALSE" are multi-token,
  corrupting every causal number in a way that reads as a weak causal effect.
  It now asserts single-token. (At 9B they ARE single tokens — verified.)

THREE METHOD FACTS WORTH NOT RE-LEARNING
  1. NIE's denominator is the MODEL's readout gap, not a property of theta. It
     grew 8.0x from 2B to 9B. Quote raw logit shifts alongside every NIE or the
     cross-scale comparison is meaningless (see section 0).
  2. theta_combo = 1/2(theta_A+theta_B) is SHORTER than either constituent
     unless they are aligned, so singleton-vs-combo NIE confounds direction with
     push magnitude. This is NOT an implementation bug — adding the raw
     mass-mean IS M&T's normalization (p(mu-+theta)=p(mu+) holds identically
     when theta = mu+ - mu-) — but that normalization is PER-PROBE and does not
     equalize two different probes. RESCALE_TO in aux_nie_intervention.py is the
     fix; it is what turned the cities arm from confounded into a real result.
  3. The norm confound touches the CAUSAL ARM ONLY. AUROC depends only on
     ranking and positive scaling preserves rankings, so every classification
     result (transfer, bimodality, P1, P2, P3) is norm-invariant. Say so in any
     write-up so a reader does not assume the problem is broader.
  Bonus: bf16 GPU nondeterminism moves NIE by ~1.3e-3 run-to-run (2158742 vs
  2158957, identical code path) — well below every bootstrap CI, but that is the
  floor below which no NIE difference should be believed.
